    5 ## Project Overview
    6
    7 Verilog RTL design for an **SNN (Spiking Neural Network) Hardware Accelerator**. Implements a two-stage
      pipeline: `spike_processing` accumulates synaptic currents from input spikes × weights, then `neuron_pro
      cessing` integrates those currents to update neuron state and emit output spikes.
    8
    9 The sibling directories (`5_test_write_config_regs_...`, `6_about_to_add_xy_...`, etc.) are snapshot var
      iants at earlier development stages — the canonical design lives here in `snnAcc/`.
   10
   11 ## Simulation
   12
   13 Simulator is **Xcelium** (Cadence). Run from this directory:
   14
   15 ```bash
   16 bash tbAccSNN.bsh
   17 ```
   18
   19 This invokes:
   20 ```
   21 xrun -sv -gui -timescale 1ns/1ps -access wrc -top tb_acc_snn_processor \
   22   acc_snn_processor.v spike_processing.v act_index_generator.v \
   23   weight_generator.v syn_curr_update.v update_state_for_neuron.v \
   24   neuron_processing.v dataline_cache_with_xy.v slice_and_align.v \
   25   tb_acc_snn_processor.v
   26 ```
   27
   28 Waveforms: `waves.shm/` and `tb_acc_snn_processor.vcd`. Open with SimVision. Build artefacts: `xcelium.d
      /`, `xrun.log`, `xrun.history`, `xrun.key`.
   29
   30 ## Architecture
   31
   32 ### Pipeline
   33
   34 ```
   35 [Input spikes / weights]
   36         │
   37         ▼
   38  spike_processing      ─── reads: act_mem, weight_mem
   39         │              ─── writes: syn_curr_mem
   40         ▼  (sp_acc_finished triggers neuron_processing)
   41  neuron_processing     ─── reads: syn_curr_mem, bias_mem, thresh_mem, pot_mem
   42         │              ─── writes: pot_mem, spike_mem (output)
   43         ▼
   44   [Output spikes / potentials]
   45 ```
   46
   47 The synaptic current memory (`syn_curr_mem`) is **shared** between both stages. Arbitration is in `acc_s
      nn_processor` with **fixed priority to `neuron_processing`**. Grants are cycle-by-cycle (no burst lock).
       The losing module sees `mem_wait_i` asserted until the bus is free.
   48
   49 ### Modules
   50
   51 | File | Module | Role |
   52 |---|---|---|
   53 | `acc_snn_processor.v` | `acc_snn_processor` | Top-level: instantiates both stages, arbitrates syn_curr
      _mem, hosts AXI config registers |
   54 | `spike_processing.v` | `spike_processing` | Stage 1: drives act_index_gen, act_cache, weight_gen, syn_
      curr_update |
   55 | `neuron_processing.v` | `neuron_processing` | Stage 2: cycles over neurons, reads currents/bias/thresh
      /pot, writes updated state |
   56 | `act_index_generator.v` | `act_index_generator` | Generates activation memory addresses; supports full
      /sparse/conv via `weight_mode_i` |
   57 | `weight_generator.v` | `weight_generator` | Computes weight memory addresses from input spike position
       and kernel parameters |
   58 | `dataline_cache_with_xy.v` | `dataline_cache_with_xy` | Single-entry cache for any memory interface; e
      xtracts sub-word slices via `slice_and_align` |
   59 | `syn_curr_update.v` | `syn_curr_update` | Read-modify-write: fetches 32-bit syn_curr word, adds sign-e
      xtended weight, writes back |
   60 | `update_state_for_neuron.v` | `update_state_for_neuron` | 2-cycle pipeline: cycle 1 = integrate + deca
      y syn_curr; cycle 2 = threshold + decay potential |
   61 | `slice_and_align.v` | `slice_and_align` | Extracts a variable-width sub-field from a 32-bit word; gene
      rates `last_slice_o` |
   62 | `constants.v` | — | Global `` `define `` constants for bus widths (included by all modules) |
   63 | `tb_acc_snn_processor.v` | `tb_acc_snn_processor` | Testbench: 256×32-bit SRAM models, random data, 1-
      cycle read latency, 1000-cycle timeout |
   64
   65 ### AXI Config Register Map (`acc_snn_processor`)
   66
   67 Address match: `sys_addr_i[31:16] == TGT_CONFIG_BASE_ADDR[31:16]`. Register select on `sys_addr_i[7:0]`:
   68
   69 | Offset | Register |
   70 |--------|----------|
   71 | `0x00` | `sp_act_base_addr_r` |
   72 | `0x04` | `sp_weight_base_addr_r` |
   73 | `0x08` | `syn_curr_base_addr_r` (shared) |
   74 | `0x0C` | `sp_weight_sz_r` |
   75 | `0x14` | `sp_total_timesteps_r` |
   76 | `0x20` | `np_num_neurons_r` |
   77 | `0x28` | `np_bias_curr_base_addr_r` |
   78 | `0x2C` | `np_thresh_base_addr_r` |
   79 | `0x30` | `np_pot_base_addr_r` |
   80 | `0x34` | `np_syn_curr_sz_r` |
   81 | `0x38` | `np_bias_curr_sz_r` |
   82 | `0x3C` | `np_pot_sz_r` |
   83 | `0x40` | `bin_point_syn_curr_r` |
   84 | `0x44–0x5C` | Grid/kernel size registers (in/out X/Y, stride, packing) |
   85
   86 `sys_ack_o` is asserted combinationally on the same cycle as `sys_req_i` when the address matches.
   87
   88 ### Key Design Patterns
   89
   90 **Valid/taken handshake** — the universal flow-control protocol. Producer asserts `*_valid_o`; consumer
      asserts `*_taken_i` to consume. Data is held stable until taken. Used across all inter-module interfaces
       (act_index, weight_index, weight_value, slice_data, neuron result).
   91
   92 **`dataline_cache_with_xy` slice encoding** — `slice_sz_i` selects element width packed in a 32-bit word
      :
   93
   94 | `slice_sz_i` | Element width |
   95 |---|---|
   96 | `3'b000` | 1-bit |
   97 | `3'b001` | 2-bit |
   98 | `3'b010` | 4-bit |
   99 | `3'b011` | 8-bit |
  100 | `3'b100` | 16-bit |
  101 | `3'b101` | 32-bit |
  102
  103 The cache is one entry deep. A memory fetch is issued when `sys_req_i` is asserted and the address misse
      s. Data arrives the next cycle (1-cycle SRAM latency); `sys_wait_o` back-pressures the upstream index ge
      nerator during a miss.
  104
  105 **`update_state_for_neuron` 2-cycle pipeline** — Cycle 1: `mul_a = syn_curr_i`, decayed syn_curr is regi
      stered. Cycle 2: `mul_a = potential_r`, decayed potential is the final output. `result_valid_o` is only
      high on cycle 2. If a spike fires, `potential_o` is zeroed (reset-to-zero model).
  106
  107 **Memory interface convention** — synchronous SRAM: address/write-data/read-data/write-enable/chip-selec
      t. Reads return data one cycle after the address (matches the testbench SRAM model).
  108
  109 ### Connectivity Modes (`weight_mode` in `act_index_generator`)
  110
  111 | `weight_mode_i` | Mode |
  112 |---|---|
  113 | `2'b00` | Full (dense) connectivity |
  114 | `2'b01` | Sparse |
  115 | `2'b10` | Convolutional |
  116
  117 Currently `weight_mode` is hardcoded to `2'b0` in `spike_processing.v` — sparse and conv paths are stubb
      ed.
  118
  119 ### Known Incomplete Areas
  120
  121 Several modules contain `// TODO` / `// XXXXX` stubs that are under active development:
  122
  123 - **`neuron_processing.v`**: `neuron_update_complete` is tied to `1'b0` (loop never exits); `get_next_sy
      n_curr_value`, `get_next_bias_curr_value`, `get_next_pot_value` are all `1'b0`; `syn_curr_mem_wr_o` and
      `pot_mem_wr_o` write-backs are `1'b0`; output spike assembly is missing.
  124 - **`spike_processing.v`**: `finished_timestep` is `1'b0`; `weight_mode` is hardcoded `0`.
  125 - **`update_state_for_neuron.v`**: `mul_result` uses `*` (inferred multiplier); signed/unsigned mixing o
      n `mul_b` is intentional (Q0.32 decay factor).

 Plan: Writeback updated_syn_curr and updated_potential in neuron_processing

 Context

 After update_state_for_neuron produces decayed updated_syn_curr and updated_potential for each neuron, both
 values are currently dropped — the memory write-enables are permanently tied to 1'b0. These must be written
 back to syn_curr_mem and pot_mem respectively. The write must not cause a full pipeline stall: instead, it runs
  in the 1-cycle gap between result_taken and the point at which the next neuron's neuron_valid can possibly
 fire, which is at minimum 3 cycles later (cache miss → memory latency → update_state_for_neuron cycle 1).

 ---
 File Modified

 snnAcc/neuron_processing.v only.

 ---
 Key Timing Analysis

 For neuron N, on cycle T when result_taken fires:
 - neuron_counter_r = N (increments to N+1 at the next clock edge)
 - updated_syn_curr and updated_potential are stable outputs from update_state_for_neuron (cycle 2 of its
 pipeline)
 - Both syn_curr and pot caches have a hit for address N → cache_mem_rd = 0 (no ongoing read)

 On cycle T+1:
 - Writeback pending flags are set; writes are asserted
 - neuron_counter_r = N+1, but caches are held off (see below)

 The cache cannot deliver valid data for N+1 until a memory read completes (1-cycle latency after the read
 request, which is suppressed while writeback is pending). So neuron_valid for N+1 cannot fire until T+3 at the
 earliest, giving at minimum 2 clear cycles for the write to complete before any new result is produced.
