❯ i want to implement the two other weight modes that I've not done yet. I've got 'fully-connected'  
  but there is also 'convolutional' and 'sparse'. In convolutional, an input neuron is not connected 
   to every neuron in the next layer, but uses a kernel that is the same for each input neuron. The  
  kernel has a size given by new configuration registers called out_x_kernel_sz_i,                   
  out_y_kernel_sz_i, whose maximum size in bits is specified using input parameters X_KERNEL_SZ and  
  Y_KERNEL_SZ. to simplify computation, we explicitly provide the size of the surrounsd for each     
  pixel, using new input configuration registers out_x_kernel_offset_i and out_y_kernel_offset_i,    
  whose maximum sizes in bits are given by parameters X_KERNEL_OFF_SZ and Y_KERNEL_OFF_SZ,           
  respectively. These are the only connections from that input neuron to the next layer. The         
  2-dimensional weight kernel is packed in memory as a linear array row by row. The weights can be   
  of any power of 2 in size, from 1-bit to 32-bit, as specified in the existing weight_sz_i          
  configuration input. The indexing of the input neuron does not need to increment by one in the X   
  or Y directions. Instead it steps by an amount given in new configuratioh registers                
  x_kernel_step_i of size given by parameter X_STEP_SZ bits, and y_kernel_step_i of size given by    
  parameter Y_STEP_SZ bits. This set of weight indices will be generated in the pre-existing         
  weight_generator block in the same way that fully-connected methdo does, except that the           
  weight_mode is set to 2'b010. The weight_mode_i signal, which is hard coded in spike_processing at 
   the moment, should be modelled as a configuration register and assigned a value in the testbench. 
   Does this make sense?

 Plan: Convolutional Connectivity Mode (weight_mode_i = 2'b10)                                       

 Context

 The SNN accelerator currently supports only fully-connected mode. weight_mode is hardcoded to 2'b00
  in spike_processing.v (line 223). The weight_generator and act_index_generator modules already
 declare the ports needed for convolutional and sparse mode (kernel size, step) — but the bodies
 have no mode-specific logic; iteration is identical for all three modes.

 This plan adds convolutional mode (2'b10) so each input spike fans out through a 2-D kernel into a
 window of output neurons. Sparse mode (2'b01) is deferred to a separate effort.

 Design Decisions (confirmed)

 - Output formula: out_x = x_in * x_kernel_step - x_kernel_offset + kx, same for out_y.
 Multiplication only, no division. Intermediate must be signed (kx − offset can be negative).
 - OOB handling: silently skip — suppress weight_index_valid_o for out-of-bounds projected outputs,
 but still advance the kernel-weight slice pointer so the weight cache stays in lockstep.
 - Kernel weight memory: one shared kernel block at weight_base_addr_i, no act_data_idx_i term in
 conv mode. Weights stored row-major: slot (kx, ky) at flat index ky * x_kernel_len_i + kx.
 - Port naming: keep existing x_kernel_len_i / y_kernel_len_i / x_kernel_step_i / y_kernel_step_i.
 Add new x_kernel_offset_i / y_kernel_offset_i (parameter widths X_KERNEL_OFF_SZ / Y_KERNEL_OFF_SZ
 already exist).
 - act_index_generator: no code changes — its existing 2-D sweep over all input pixels is correct
 for conv (every input contributes).

     Run from snnAcc/:
     bash tbAccSNN.bsh                                                                             
                                
     Expected behaviors (4×4 input, 3×3 kernel, stride 1, offset 1, output 4×4)
                                                       
     1. Total emit count across all 16 input neurons: corner inputs emit 4, edge non-corner emit 6,
     interior emit 9 → 4*4 + 8*6 + 4*9 = 100 valid weight_index_valid_o pulses per timestep.
     2. weight_index_x_o / weight_index_y_o: when weight_index_valid_o is high, both must be in [0, 
     4).                                                                            
     3. weight_row_base_addr: equals 0x2000 for every input neuron in conv mode (noact_data_idx_i
     term).
     4. out_elem_count_r: walks 0..8 for every input neuron and resets between input neurons. Every
     kernel slot is visited (taken OR skipped) — no slot is skipped twice or stalled.
     5. Sum on output neuron (1,1) (fully covered interior) — assuming dense unit input activations
     and kernel weights 1..9 — should equal sum(1..9) = 45 after all 16 inputs are processed.
                                                                                                     
     Debug aids to include during bring-up
                                                                                 
     - $display inside the conv branch printing (act_x, act_y, kx, ky, out_x, out_y, oob_skip) on
     every next_kernel_pos. 
     - Simulation-only assertion: when weight_index_valid_o is high, weight_index_x_o < out_x_len_i
     and weight_index_y_o < out_y_len_i.                 
                                
     Follow-up scenarios (not in this plan but useful next)

     - stride > 1 (e.g. 2×2 input, 3×3 kernel, stride 2, output 5×5).             
     - Asymmetric kernel (3×1 with y_kernel_offset = 0).
     - kernel_offset = 0 (no centering — kernel anchored at top-left of fan-out region).

     Plan: Convolutional Connectivity Mode (weight_mode_i = 2'b10)                                   
                                                                                                 
     Context                                                                                         
                                                                                                 
     The SNN accelerator currently supports only fully-connected mode. weight_mode is hardcoded to   
     2'b00 in spike_processing.v (line 223). The weight_generator and act_index_generator modules
     already declare the ports needed for convolutional and sparse mode (kernel size, step) — but the
      bodies have no mode-specific logic; iteration is identical for all three modes.

     This plan adds convolutional mode (2'b10) so each input spike fans out througha 2-D kernel into
      a window of output neurons. Sparse mode (2'b01) is deferred to a separate effort.

     Design Decisions (confirmed)

     - Output formula: out_x = x_in * x_kernel_step - x_kernel_offset + kx, same for out_y.
     Multiplication only, no division. Intermediate must be signed (kx − offset canbe negative).
     - OOB handling: silently skip — suppress weight_index_valid_o for out-of-bounds projected
     outputs, but still advance the kernel-weight slice pointer so the weight cachestays in
     lockstep.
     - Kernel weight memory: one shared kernel block at weight_base_addr_i, no act_data_idx_i term in
      conv mode. Weights stored row-major: slot (kx, ky) at flat index ky * x_kernel_len_i + kx.
     - Port naming: keep existing x_kernel_len_i / y_kernel_len_i / x_kernel_step_i/
     y_kernel_step_i. Add new x_kernel_offset_i / y_kernel_offset_i (parameter widths X_KERNEL_OFF_SZ
      / Y_KERNEL_OFF_SZ already exist).
     - act_index_generator: no code changes — its existing 2-D sweep over all inputpixels is correct
      for conv (every input contributes).

     input  wire [X_KERNEL_OFF_SZ-1:0] x_kernel_offset_i,
     input  wire [Y_KERNEL_OFF_SZ-1:0] y_kernel_offset_i,

     reg  [X_KERNEL_SZ-1:0] kernel_x_count_r;
     reg  [Y_KERNEL_SZ-1:0] kernel_y_count_r;

     - kernel_y_count_r increments on next_kernel_pos & kernel_x_at_end, wraps to 0on

     out_x_proj_signed = $signed({1'b0, act_data_x_i}) * $signed({1'b0, x_kernel_step_i})

                       + $signed({1'b0, kernel_x_count_r});

 Plan: Sparse Connectivity Mode (weight_mode_i = 2'b01) 

 Context

 Conv mode (2'b10) is now implemented. Sparse mode (2'b01) is the remaining stub. In sparse mode
 each weight memory entry is a tuple that bundles (output_index, weight_value) for that connection —
  explicit-list sparse connectivity. Input neurons are still iterated in raster order, but only the
 listed (idx, wgt) tuples are processed for each input neuron.

 The key new piece is a parameterised tuple unpacker that splits the cache-fetched tuple into its
 index and weight fields. Existing iteration, weight cache, valid/taken handshake, and
 syn_curr-update read-modify-write are reused unchanged where possible.

 Design Decisions (confirmed)

 - Tuple layout (left-justified everywhere):
   - Tuple total size in bits = 2 × max(weight_size, index_size) (a power of 2, ≤ 32).
   - Upper half-slot = index field; lower half-slot = weight field.
   - Within each half-slot, the actual value is left-justified (in the slot's MSBs); any padding
 sits in the slot's LSBs.
   - Cache delivers the tuple left-justified in the 32-bit slice port (existing slice_and_align
 convention), so within weight_value_o:
       - actual index occupies bits [31 : 32 - index_size]
     - actual weight occupies bits [31 - tuple_size/2 : 32 - tuple_size/2 - weight_size]
 - Fan-out per input neuron: fixed N for all inputs, configured by a new sp_sparse_count_r register.
 - Tuple size: explicit config register (sp_tuple_sz_r); testbench writes it to be consistent with
 weight_sz and the new index_sz.
 - Addressing: syn_curr_update gets two new inputs (weight_mode_i, sparse_index_i);in sparse mode
 it bypasses the y * out_x_len + x calculation and uses sparse_index_i directly.
 - Iteration in weight_generator: reuse the existing out_elem_count_r counter (full-mode logic), but
  in sparse mode end-of-pass-for-this-input fires when out_elem_count_r == sp_sparse_count_r - 1
 instead of the X×Y grid sweep.
 - weight_row_base_addr: keep the existing full-mode formula act_data_idx_i * rows_per_neuron_i +
 weight_base_addr_i — sparse rows are sized so each input neuron has its own row ofN tuples.
 - Constraint: weight_size ≤ tuple_size/2 and index_size ≤ tuple_size/2. Max tuple = 32-bit, so max
 field = 16-bit.

 Pseudocode:
 // actual_index: top index_size bits of weight_value_o
 case (index_sz_i)

    3'b001: actual_index = {30'b0, weight_value_o[31:30]};

    {3'b011, 3'b000}: actual_weight = weight_value_o[27];          // 8-bit tuple, 1-bit weight

 Test setup

 - 4×4 input grid (16 input neurons), all spiking (act memory pre-loaded with 0xFFFFFFFF).
 - weight_sz = 8, index_sz = 8, tuple_sz = 16, sparse_count = 2 per input.
 - Pre-load weight memory: row N = {tuple0_for_input_N, tuple1_for_input_N} packed as a 32-bit word
 at weight_base_addr + N.
 - Tuple values chosen so each input neuron projects to two distinct outputs with traceable weights
 (e.g., input N → outputs (N) mod 16 and (N+1) mod 16, weights (N+1) and (N+2)).

 Expected behaviors

     weights (e.g., input N → outputs (N) mod 16 and (N+1) mod 16, weights (N+1) and (N+2)).

     Expected behaviors

     1. Total syn_curr writes from spike_processing: 16 inputs × 2 tuples = 32 writes per timestep
     (no OOB skipping in sparse mode).
     2. syn_curr_mem_addr_o: each write address = syn_curr_base + actual_index, where actual_index is
      the upper-half byte of the fetched tuple.
     3. syn_curr_mem_data_o: equals previous syn_curr value plus sign-extended actual_weight
     (lower-half byte).
     4. weight_mem_addr_o advances once per input neuron (since rows_per_neuron = 1and
     weights_per_word = 2).
     5. Pipeline completion: sp_finished_o pulses cleanly within ~200 cycles for this 32-write
     workload; no timeout.

     Hand-trace check

     For input neuron 0 with weight_mem[0] = 32'h0501_0A02 (tuples {idx=5, wgt=1} and {idx=10,
     wgt=2}, left-justified packing):
     - syn_curr write 1: addr = base + 5, data = mem_read + 1
     - syn_curr write 2: addr = base + 10, data = mem_read + 2

     Confirm both writes land at the expected addresses with the expected data via the existing
     per-cycle log line.
