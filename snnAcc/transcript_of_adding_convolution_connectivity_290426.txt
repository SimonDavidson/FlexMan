❯ i want to implement the two other weight modes that I've not done yet. I've got 'fully-connected'  
  but there is also 'convolutional' and 'sparse'. In convolutional, an input neuron is not connected 
   to every neuron in the next layer, but uses a kernel that is the same for each input neuron. The  
  kernel has a size given by new configuration registers called out_x_kernel_sz_i,                   
  out_y_kernel_sz_i, whose maximum size in bits is specified using input parameters X_KERNEL_SZ and  
  Y_KERNEL_SZ. to simplify computation, we explicitly provide the size of the surrounsd for each     
  pixel, using new input configuration registers out_x_kernel_offset_i and out_y_kernel_offset_i,    
  whose maximum sizes in bits are given by parameters X_KERNEL_OFF_SZ and Y_KERNEL_OFF_SZ,           
  respectively. These are the only connections from that input neuron to the next layer. The         
  2-dimensional weight kernel is packed in memory as a linear array row by row. The weights can be   
  of any power of 2 in size, from 1-bit to 32-bit, as specified in the existing weight_sz_i          
  configuration input. The indexing of the input neuron does not need to increment by one in the X   
  or Y directions. Instead it steps by an amount given in new configuratioh registers                
  x_kernel_step_i of size given by parameter X_STEP_SZ bits, and y_kernel_step_i of size given by    
  parameter Y_STEP_SZ bits. This set of weight indices will be generated in the pre-existing         
  weight_generator block in the same way that fully-connected methdo does, except that the           
  weight_mode is set to 2'b010. The weight_mode_i signal, which is hard coded in spike_processing at 
   the moment, should be modelled as a configuration register and assigned a value in the testbench.

 Plan: Convolutional Connectivity Mode (weight_mode_i = 2'b10)                                       

 Context

 The SNN accelerator currently supports only fully-connected mode. weight_mode is hardcoded to 2'b00
  in spike_processing.v (line 223). The weight_generator and act_index_generator modules already
 declare the ports needed for convolutional and sparse mode (kernel size, step) — but the bodies
 have no mode-specific logic; iteration is identical for all three modes.

 This plan adds convolutional mode (2'b10) so each input spike fans out through a 2-D kernel into a
 window of output neurons. Sparse mode (2'b01) is deferred to a separate effort.

 Design Decisions (confirmed)

 - Output formula: out_x = x_in * x_kernel_step - x_kernel_offset + kx, same for out_y.
 Multiplication only, no division. Intermediate must be signed (kx − offset can be negative).
 - OOB handling: silently skip — suppress weight_index_valid_o for out-of-bounds projected outputs,
 but still advance the kernel-weight slice pointer so the weight cache stays in lockstep.
 - Kernel weight memory: one shared kernel block at weight_base_addr_i, no act_data_idx_i term in
 conv mode. Weights stored row-major: slot (kx, ky) at flat index ky * x_kernel_len_i + kx.
 - Port naming: keep existing x_kernel_len_i / y_kernel_len_i / x_kernel_step_i / y_kernel_step_i.
 Add new x_kernel_offset_i / y_kernel_offset_i (parameter widths X_KERNEL_OFF_SZ / Y_KERNEL_OFF_SZ
 already exist).
 - act_index_generator: no code changes — its existing 2-D sweep over all input pixels is correct
 for conv (every input contributes).

     Expected behaviors (4×4 input, 3×3 kernel, stride 1, offset 1, output 4×4)
                                                       
     1. Total emit count across all 16 input neurons: corner inputs emit 4, edge non-corner emit 6,
     interior emit 9 → 4*4 + 8*6 + 4*9 = 100 valid weight_index_valid_o pulses per timestep.
     2. weight_index_x_o / weight_index_y_o: when weight_index_valid_o is high, both must be in [0, 
     4).                                                                            
     3. weight_row_base_addr: equals 0x2000 for every input neuron in conv mode (no act_data_idx_i
     term).
     4. out_elem_count_r: walks 0..8 for every input neuron and resets between input neurons. Every
     kernel slot is visited (taken OR skipped) — no slot is skipped twice or stalled.
     5. Sum on output neuron (1,1) (fully covered interior) — assuming dense unit input activations
     and kernel weights 1..9 — should equal sum(1..9) = 45 after all 16 inputs are processed.
                                                                                                     
     Debug aids to include during bring-up
                                                                                 
     - $display inside the conv branch printing (act_x, act_y, kx, ky, out_x, out_y, oob_skip) on
     every next_kernel_pos. 
     - Simulation-only assertion: when weight_index_valid_o is high, weight_index_x_o < out_x_len_i
     and weight_index_y_o < out_y_len_i.                 
                                
     Follow-up scenarios (not in this plan but useful next)

     - stride > 1 (e.g. 2×2 input, 3×3 kernel, stride 2, output 5×5).             
     - Asymmetric kernel (3×1 with y_kernel_offset = 0).
     - kernel_offset = 0 (no centering — kernel anchored at top-left of fan-out region).
