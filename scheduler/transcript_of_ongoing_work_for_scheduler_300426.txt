● Here are the unfinished blocks I found in scheduler.v and tb_scheduler.v:
                                                                                                                   
  scheduler.v                                                                         
                                                                                                                   
  1. fill_complete is hardwired to 0 (line 397: assign fill_complete = 1'b0;//TODO).                               
  The FILL instruction will hang forever — inst_consumed for FILL requires fill_complete, which never asserts. The 
  entire FILL state machine described in the comment block (lines 350–397) is missing — no memory address          
  generation, no buffer write, no completion logic, no use of the second 32-bit word of the FILL instruction.
  2. tgt_selected decoder is incomplete (lines 357–394). Only IDs 0–15 are decoded; entries for 16–31 are commented
   out, so the design will silently miss-decode any FILL targeting buffers 16–31. (Currently moot because          
  NUM_BUFFERS=16, but it will break the moment the spec value of 32 is adopted.) tgt_selected is also computed but
  never consumed — the tgt_free line that would have used it is commented out at line 396.                         
  3. CHECK instruction "finish-on-success" is not fully wired.
    - prog_stopping_r is set on a successful check-with-mode=1 (lines 212–213) but there is no logic to cancel     
  matching-colour tasks already in the table (the spec requires this).                                             
    - There is no CONTINUE handling — nothing listens for the CONTINUE control register to come out of the         
  finish-on-success halt.                                                                                          
  4. AXI / system bus interface is dangling. sys_req_i, sys_ack_o, sys_data_i, sys_data_o are declared on the port
  list but never referenced anywhere in the body. None of the documented control regs (LOAD_PC, START, CONTINUE,   
  PAUSE, UNPAUSE) or status regs (CURRENT_PC, ACTIVE, BUFF_FULL, BUFF_BUSY, BUFF_COLOUR, per-buffer status) are
  decoded or driven. There is also no "finished" signal back to the host CPU after STOP.                           
  5. d[ENTRY_SBUFF3_END:ENTRY_SBUFF3_START] is a copy of src2 (line 325, marked // Duplicate!). The TASK encoding
  in CLAUDE.md only defines src1/src2 — but the entry layout reserves a third source field that is currently being 
  filled with a duplicate. Either the third source needs a real source in the instruction encoding, or the entry
  layout should drop it.                                                                                           
  6. delete_entry_i to sch_table is tied to 0 (line 418). There is no path to remove an entry on CHECK-cancel or
  other failure modes.                                                                                             
  7. Reset list is incomplete (lines 223–230). word_ready_r has its own reset block, but loop_counter_r /
  loop_restart_r are reset in a separate always — fine — yet tgt_selected (a reg) and the decode-output regs       
  (inst_is_*) are combinational-style and never reset. That's intentional since they're driven combinationally;
  just flagging that nothing else needs resetting.                                                                 
  8. NUM_BUFFERS = 16 vs spec 32. The spec calls for 32 buffers; RTL is hardcoded to 16 in places (the tgt_selected
   decoder above, and the parameter default). This is a known gap per CLAUDE.md but worth flagging as unfinished.  
   
  tb_scheduler.v                                                                                                   
                  
  1. No CHECK / JUMP / FILL / LOOP / LOOPEND coverage. The program is 30 TASKs + STOP. None of the other opcodes   
  are exercised, so the unfinished logic above is also untested.
  2. prog_mem_wait is tied to 0 (line 250) and never wiggled. No back-pressure stress on the fetch path.           
  3. test_stall_pipe is tied to 0 (line 179). The pipe-stall path through inst_consumed is never exercised.        
  4. AXI ports are stubs (lines 180–183: sys_req_i=0, sys_ack_o/sys_data_o left open, sys_data_i=0). Consistent    
  with the DUT not implementing them, but means the testbench has no host-CPU model.                               
  5. finish_count termination is racy (lines 224–228). It samples finish_count + acc_finished_w[0] +               
  acc_finished_w[1] >= 30 before the non-blocking assignment commits, which works for the ">=" test but reads      
  awkwardly; more importantly, there is no check that dispatch_count also reached 30, so an early termination is
  possible if accelerators ever spuriously asserted finished_o (they don't here, but it's brittle).                
  6. No assertion that STOP actually halts the fetcher. The TB ends when 30 finishes are seen, never verifying that
   the scheduler stops issuing memory requests after STOP.                                                         
  7. No colour-mismatch / out-of-order-write hazard test. Every TASK uses colour=0; the colour-flip logic on buffer
   drain is never functionally checked.                                                                            
  8. No multi-program / re-start test. Spec says STOP followed by a new program resets buffer/accelerator state —
  never exercised.                                                                                                 
                  
  Want me to draft fixes for any of these (e.g. wiring up fill_complete, completing the tgt_selected decoder, or   
  adding CHECK/LOOP coverage to the testbench)?
